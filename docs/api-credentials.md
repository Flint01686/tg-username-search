# Как получить api_id и api_hash

Скрипт читает их из файла `.env` в корне репозитория. В чат и в git эти значения класть не нужно: `.env` уже в `.gitignore`.

1. Открой [my.telegram.org](https://my.telegram.org) и войди номером телефона. Код придёт в Telegram.
2. Открой раздел **API development tools**.
3. Если приложения ещё нет, создай его. Название любое, например `username-check`. Платформа — Desktop. Короткое имя тоже любое, латиницей.
4. На странице будут два поля: **App api_id** (число) и **App api_hash** (длинная строка).

## Если сайт пишет Too many attempts

С российского адреса [my.telegram.org](https://my.telegram.org) на создание приложения отвечает одной и той же строкой: `Too many attempts. Please try again later.` Форма при этом заполнена, лишних нажатий нет, описание на месте. Другой аккаунт получает то же самое.

VPN положение не меняет. Сайт видит выход VPN так же, как адрес, с которого форму уже не открывают, и отдаёт ту же строку. Это не счётчик кликов и не пустое поле.

Свою пару всё равно нужно получить самому и хранить только в `.env`. В репозиторий её класть нельзя.

Вход в этом проекте до конца не доведён. Telegram отдавал код только внутрь уже открытого приложения (`SentCodeTypeApp`), без SMS и без почты: поле `next_type` было пустым. Код в служебном чате при этом не появлялся. Опубликованная пара Android сервер отвергает как уже засвеченную. С российского адреса своё приложение на сайте не создаётся, VPN получает ту же строку.

Создай `.env` рядом с `.env.example`:

```text
TG_API_ID=12345678
TG_API_HASH=0123456789abcdef0123456789abcdef
```

Без кавычек и без пробелов вокруг `=`.

Дальше один раз войти из корня репозитория:

```text
python check.py --login
```

Скрипт спросит номер и код из Telegram и сохранит сессию в `tg.session`. Этот файл тоже не коммитится. После входа проверка маски тем же методом, что поле в настройках:

```text
python check.py --mt zovXX zovXXX
```
